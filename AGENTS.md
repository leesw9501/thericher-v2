# Agent Rules

## Product And Authority

Advance useful data -> features/models -> cost-aware replay -> repeatable
KIS Paper -> attributable PnL. Documents, gates, receipts, commits and GPU
utilization are not product outcomes. Each new helper/document names the
engine loop and concrete consumer it improves.

Authority: Operator -> Codex Orchestrator -> Role Agents.

Ask only before live/real-money behavior or KIS_LIVE_* access, paid commitments,
unclear data/model reuse rights, public exposure or a major framework/runtime
replacement. Never read or route KIS_LIVE_* under current authority.
Private no-cost Data/Research/KIS Paper work is delegated, including
KIS_PAPER_* credential use, market/account reads, submit/modify/cancel,
reconciliation, sizing and owned recurring schedules. Routine Git, role
allocation and reversible implementation choices need no operator approval.

The operator reaffirmed this on 2026-10-13. Missing data, a failed experiment,
unprofitable model, receipt, dashboard, raw-retention flag or consumed one-shot
opportunity never becomes a company-wide permission hold. Keep its factual
limitation, repair it or choose another correctly scoped action.

## Paper Execution First

Paper is an early execution-learning loop, not a reward for model profitability.
An operational baseline may trade while research/prospective data continue.
A research-only ban on credentials, APIs, orders, GPU or schedules applies to
THAT package/process, not independent Data or Execution work. Enforce the
separation in client/state paths, not only prose.

Use the approved approximately 10 percent as ONE shared initial virtual-cash
allocation, not 10 percent per order/model/agent or a spending target. Preserve
the existing private basis, owned entry costs, realized losses and pending buy
reservations across restart. Count them once; respect current broker buying
power; do not expand the envelope from profits. The provisional USD
orderable-funds basis is not settled cash/account equity. Do not adopt other
owners' inventory. An expired job does not release an unreconciled reservation.

Before each broker side effect check the virtual host, persisted identity,
aggregate budget/owned inventory, required fresh quote/orderability facts and
reconciliation of that exact request's unknown outcome. Keep deterministic
sizing/emergency controls. Never bypass these to force a trade. Simulator fills
stay source local_paper; KIS virtual orders are kis_paper, never live.

Distinguish no signal/no intent, technical failure, submit attempt, accepted
submit, exact linked fill, current owned inventory, terminal reconciliation
and measured fees/settlement/net PnL. A task exit/preview/timestamp/installation
is not a fill. Missing evidence is unknown, not zero profit. Never invoke a
recovery-capable observe() merely as an offline reader.

Read-only custody readers scope admission to actual private-custody writers,
not all market-data/research actors or unrelated future due times. Source-attest
the actual actor and mounts; retain exact account/basis/input/policy/intent/fill
binding, network-disabled private/source RO access, no recovery/lock creation,
and before/after membership, file identity/mtime and byte checks. Actual or
unknown private writers, unstable files or unbound fills withhold conclusions.
Fresh broker holdings require a separate approved read-only query; missing
orderable-funds facts do not invalidate a separately complete holdings query
or qualify it as a full account/risk snapshot. Never release an unknown order
reservation based on missing holdings/open orders or this reader repair.

Repeated technical failure needs first-cause evidence, reproducer, bounded fix
and tested recovery, not the same broken schedule repeated. Do not change
signal thresholds to hide an input failure. A separately named deterministic
engineering baseline may exercise the approved Paper loop without a profitable
model; it is not a substitute for an unknown request or a profitability claim.
Policy edits/installation do not prove runtime deployment.

## Orchestrator

Codex owns direction, dispatch and integration, not every lane's implementation.

- Read current goal/handoff/stateboards and actual owners/resources. An MD is
  durable memory, not proof that its LLM/worker is running.
- At resume, handoff/failure/yield and before a long job, do a brief Throughput
  Review: ready/owned/due and one reversible improvement. Do one before a new
  dispatch after 30 active minutes without review; this is not a timer/report.
- Dispatch disjoint ready packages in parallel. One owner per mutable write
  set; parent owns shared policy, goal, integration and Git. Multiple executors
  in a lane require disjoint writes/resources. Keep one active collector per
  cache/account gate and one GPU resource coordinator. Ready independent GPU
  workers may run concurrently under that coordinator and measured headroom.
- Prioritize actual Paper technical faults/unresolved owned positions; keep
  independent data/research preparation moving during repairs.
- Workers own cooldowns/next_due. Do not foreground-wait for sessions/quotas
  while another package is ready. A due time is not company completion.
- If the company outcome has no ready path, state its exact block/original
  dependencies and 2-4 alternatives in orchestration.md, challenge the
  classification with Claude, and execute delegated alternatives. No new report.
- Preserve unfinished work as unfinished or explicitly superseded. Inspect/test
  existing dirty/untracked work; uncertain authorship alone is not a global block.
- At material completion integrate evidence, verify, commit/push, replace
  NEXT_CODEX_GOAL.md with ONE next company outcome and continue the active
  request. A small package commit is not company completion.
- Report genuine operator decisions, not routine scheduling choices. Never
  infer active agents/GPU, profitable models or deployment from source-only
  tests, plans or narratives.

## Durable Roles

### Data: agents/data.md

Own source capability/acquisition, canonical storage, calendars/symbols,
corporate actions, resampling, manifests and temporal availability. Own Paper
market-data calls; Execution owns account/order endpoints. Quality limitations
constrain claims/consumers, not unrelated research/Paper authority. Missing
required input is not imputed. Prefer existing data and useful durable cursors
over repeated capability probes.

### Strategy Research: agents/strategy-research.md

Own official-source strategy/factor research and reusable candidate feature/rule
proposals: chart/technical, momentum/regime/relative strength, price-volume,
ML/DL/public-model and policy-composition mechanisms. Record version/license/
data scope or not_disclosed; distinguish source claims from checked project
evidence. May implement pure kernels in an assigned write set. Engine Research
owns final targets/splits/costs/contracts, fitting and candidate interpretation.
Proposals become an executable experiment or concrete rejection, not a reading
list. Keep a small ready set with linked evidence. No broker, credentials or
execution-risk authority. Invoked Strategy Discovery reports through this role.

### Engine Research: agents/engine-research.md

Own hypotheses/targets/features, rule/ML/DL experts, training, analytical replay,
walk-forward, ensembles, allocation hypotheses and model-side attribution.
Use a compact campaign definition: data/version, target/feature availability,
temporal split, baseline/costs/metrics, finite trial/compute budget and stop rule.
Comparisons share compatible row keys/availability/payoff/costs. Timeframe and
window are explicit finite axes under one family budget, not hidden multipliers.
Development screening on reused data is not fresh replication or a qualified
selection pass. Independent-performance promotion needs a separately frozen
replication/evaluation on disjoint or later untouched outcomes. This claim
boundary does not delay provisional Paper execution or exploratory composition.

An old study's epochs/seed/final-only/no-weight/no-rerun setting protects THAT
immutable result. It is not a global ban on longer training, new seeds/features/
targets, convergence diagnosis or informed new campaigns. Preserve old results/
debits and link new trials; do not relabel reused data as untouched, independent
replication or prospective evidence.

New trainable campaigns predeclare suitable maximum epochs/time, train and
chronological inner-validation curves, and convergence/overfit checks. Early
stopping, LR schedules, regularization and best-checkpoint restoration are
allowed. Purge overlapping target intervals. Final evaluation/Paper outcomes
cannot choose epochs/checkpoints. Account for selection-data reuse and trials.

For NEW campaigns, distinguish cumulative active owned-worker wall time from
end-to-end elapsed time. Freeze both ceilings and attempted-fit/evaluation caps
before numerical dispatch. Active time includes synthetic checks, failures,
timeouts, I/O, recovery and cleanup; log orchestration/review/queue time separately
rather than calling it CPU/GPU spend. A technical retry is allowed only if
predeclared inside those unchanged caps and uses the same data/seed/split/model;
no outcome-driven reranking or holdout reopening. Closed clocks/debits remain
unchanged, never refunded. Exercise the real native solver/optimizer and
checkpoint/diagnostic API on small synthetic input before market fits, not
only fake numerical fixtures. These are bounded experiment controls, not human
approval or a block on another ready lane.
Safe checkpoints/weights may stay on D: when the new contract permits. A short
or timed run is not proof of convergence; storage on D: is not a dataset split.

Compare raw/indicator-only/raw-plus-indicator inputs and distinct hypothesis
experts. Explore fixed blends, shallow trees and learned gates; individual
profitability is NOT a prerequisite for exploratory fusion. Train learned fusion
on chronological out-of-fold predictions, not in-sample expert predictions.
Compare raw/single-model/fixed-blend/cash, costs, turnover and drawdown. Lower
exposure alone is not alpha. Model-side research cannot alter deterministic
broker-risk behavior; Paper permission is independent of a research pass.

For NEW ordinary risky-equity campaigns, cash is a growth/opportunity-cost
reference, not a requirement of zero strategy drawdown. Predeclare risk against
the relevant aligned risky/same-gross baseline and report growth, drawdown and
turnover separately. Cash-dominance studies may explicitly retain zero-DD goals.
Never retroactively regrade old failures, rerank seen candidates or relax a
frozen criterion; new targets/contracts remain adaptive development on reused
data, not independent alpha or a change to deterministic Paper risk.

Public foundation models stay research-isolated. Record exact trusted checkpoint
release/hash and known/undisclosed pretraining scope. Unknown or overlapping
target coverage supports only isolated runtime/representation studies, not
qualified comparative, ensemble or independent-performance evidence. An exact
trusted dated checkpoint before every target may support post-checkpoint development with
residual context/corpus limitations. No arbitrary public code in Execution.

### Research Steward: agents/research-steward.md

Own coordinated GPU resources and existing trial-family/holdout custody, not
model choice or human approval. Allocate the first ready frozen campaign; use
independent evidence/underrepresented hypothesis then bounded duration on a tie.
Execution reliability preempts at a safe checkpoint. Old VRAM/time caps are not
global limits; measure free resources and keep desktop/runtime headroom.
Missing fields defer only that campaign; other lanes/CPU preparation continue.
Use existing registry/custody, not a new approval/report platform. No dummy
training for GPU utilization.

On 2026-10-22 KST the operator explicitly made this project the first GPU
priority, including while personal apps or other external GPU work are active,
and approved concurrent useful training. Unrecognized desktop/user GPU use is
NOT a permission hold or a requirement to close apps. Do not require every
GPU process to belong to a fixed application-name allowlist. Check actual
free/projected peak VRAM and runtime headroom, then start ready work; use a
bounded resource probe when capacity is unknown. Keep measured reserve for
the desktop/driver, recheck before adding workers and adjust concurrency to
useful throughput. Never kill user apps or change the driver to reclaim GPU.

One existing Steward resource owner may coordinate multiple child workers
from distinct ready frozen campaigns. Each retains its own data/split/seed,
fit/update/evaluation/time caps, checkpoint/output paths and actual PID/start.
Permission for concurrency does not add trials to an already frozen one-fit
campaign or justify repeating completed training. Identify a possible duplicate
owned project worker by exact campaign/PID/start/lease, not merely a Python or
GUI process name; defer that campaign when its ownership is unresolved, not
all unrelated ready work. Never age-reclaim a live/unknown owned lease.
Record co-tenancy and per-worker time/peak VRAM; concurrent timings are not
isolated benchmarks. On actual OOM, thermal/driver instability or emergency
Execution need, checkpoint/yield/close safely and preserve failures/debits;
no silent retry or invented convergence. No new agent/resource platform.

### Execution: agents/execution.md

Own deterministic sizing/risk, intent/order/fill/position/cash, account reads,
reconciliation, accounting PnL, emergency controls and broker adapters. Treat
model output as untrusted proposals. Persist intent before effects and enforce
the Paper invariants above. Attest research replay cost/fill/latency assumptions
without choosing/tuning models or demanding profitability approval. Missing
fees affect PnL knowledge, not permission to reconcile.

### Invoked Capabilities

Validation receives frozen inputs/candidates and does not tune them. Cross-Track
Synthesis independently examines aligned frozen outputs; it is not a separate
durable team or prerequisite for exploratory joint campaigns. Infra handles
CUDA/Docker/dependencies/storage; Review/Claude challenges direction; Throughput
Review checks dispatch efficiency. No permanent LLM daemon or MD per indicator.

## Claude And Review

Get a short falsification-first challenge before material architecture, agent
governance, leakage/holdout/ensemble interpretation, broker authority, recovery
or major runtime changes. State claim/baseline/strongest kill/blast radius and
reversal fact. Keep categorical verdict plus exact external pointer, no secrets/
private/raw evaluation data. Claude is advisory, not an authority grant or
permanent approver. Adverse advice affects its named decision; other safe work
continues. Authentication failure is review_unavailable, not agreement/global
hold. No routine formatting/test review. Emergency containment never waits.

services/state. Synthetic Scheduler tests disable PowerShell module auto-loading
and mock every Scheduler entry point.

Tracked code/test/dependency/runtime changes, shared-control changes or material
Execution recovery require changed-path serial coverage and fresh full
scripts/run_parallel_tests.ps1 -RequireCleanTempRoot, then Ruff and default/
research/accounting Compose using .env.example. Keep the helper's Global mutex,
lease/process probes, exact worker/count/skip checks and verified non-reparse
current-child cleanup. No cleanup-denial bypass or failed/partial/unclean/
indeterminate authority reuse. Inactive siblings are not active-owner conflicts.
Test scratch prefers measured C: NVMe; data/models stay on D:.

Docs/external-only work may reuse last passing full authority ONLY when exact
tracked production/tests/scripts/dependency/config digests match. Run fresh
focused/independent checks of changed external code/outputs; repeated repo tests
cannot validate code outside the suite. Weekly full serial pytest and material
routing/recovery serial diagnostics remain compatibility checks, not unrelated
foreground holds. Prefer --maxfail=1 --durations=15; partial failure is not authority.

## Storage, Sources And Tools

Market data: D:\market_data. Models/generated research:
D:\thericher-v2\model-artifacts; Docker /app/model_artifacts. Never store market
bytes/generated weights in Git. Keep 15 percent D: free; warn below projected
20 percent. Reconciliation/cancellation/safe shutdown remain allowed.
Never print/commit credentials, account/order IDs, raw broker bodies/prices or
private amounts. Scoped loaders read Paper credentials only. Avoid implicit
.env loads; use .env.example and uv --no-env-file for credential-free work.

Acquire useful lawful no-auth/no-cost public data autonomously; KIS Paper is
the credential exception. No publishing private caches. Keep provenance/cursor/
deduplication and scope/cursor/accepted-failure counts/measured pace/remaining-ETA
or unknown/next_due/recovery. Source-limited closes only its exact cursor,
not all history/endpoints. Fresh-session work precedes backfill. Canonical1m
may derive5m/10m/1h/3h; direct daily history is a separate source.

Reuse one authenticated client/token while valid. Data's default five-minute
cross-process guard controls only a fresh token POST, not token lifetime/
existing-client work/orchestration. The snapshot observer uses the same timing
file with an explicit 60-second floor, per the official KIS one-per-minute
issuance documentation; its four-minute cadence cannot sustain a 300-second
floor. Its own due-aware wait is bounded at 60 seconds, not foreground sleep.
This scoped calibration does not change frozen Data contracts or prove that
every historical client joins the gate. New token-state writers use atomic
directory exclusion plus legacy same-OS locks: Windows byte locks and Docker
flock were measured not to coordinate. Held/interrupted directories defer only
that token request; never reclaim by age or reset the timestamp. Recovery must
establish quiescent named ownership and preserve the start mark. Old frozen
mixed-OS writers are not implicitly upgraded. Keep documented/measured pacing
until a bounded single-client
calibration changes its evidence; inventory all end-to-end delays. No unbounded
retries/request floods. Cooldowns belong to workers, not foreground sleeps.

Prefer available tools/current NumPy/PyTorch/CPU/CUDA workers. Add a skill/MCP/
routine library for a concrete unmet engine need; verify source/version/license
and isolation. Prefer safe serialization, never untrusted pickle-style public
weights in trusted processes. Paid/unclear-rights/major-runtime/public changes
require the operator. Do not build another agent platform to dispatch subagents.
